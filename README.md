# enzobellissimo.com

Personal blog, published with GitHub Pages (Jekyll) at
**https://blog.enzobellissimo.com**. Bilingual: English at the root,
Portuguese under `/pt/`.

---

## Write a new post

| Language | Folder | URL |
| --- | --- | --- |
| English | `_posts/YYYY-MM-DD-slug.md` | `/slug/` |
| Portuguese | `_pt_posts/YYYY-MM-DD-slug.md` | `/pt/slug/` |

The minimum is a title:

```yaml
---
title: My post title
---
Body in Markdown.
```

`layout: post`, the author, and the language are applied automatically from
the folder (see `defaults` in `_config.yml`). Use a Portuguese slug for a
Portuguese post — the URL is part of the translation.

Commit + push (or edit on github.com) → live in ~1 minute.

### Publishing a translation

Give both files the same `ref:` and they become a translation pair:

```yaml
# _posts/2026-08-25-cheap-intelligence.md      # _pt_posts/2026-08-25-inteligencia-barata.md
ref: cheap-intelligence                        ref: cheap-intelligence
```

That one key is the whole i18n contract. From it the build derives:

- the reciprocal `hreflang` cluster on both pages, plus `x-default` → English
- the PT/EN switcher in the header, which links to the *counterpart page*
  rather than dumping the reader on a home page
- `workTranslation` / `translationOfWork` in the JSON-LD

A post with no `ref` (or with no counterpart yet) is not a bug: it simply
emits no hreflang, appears only in its own language's home page and feed, and
the switcher falls back to that language's home. `validate-seo.py` reports
untranslated pages as a **warning**, so a gap is visible without failing CI.

### Front matter that moves the SEO needle

Everything below is optional, but the first two are worth 30 seconds each:

| Key | What it does |
| --- | --- |
| `description` | The `<meta description>`, the OG/Twitter blurb, the schema `description`, and the blurb on the homepage list. **Write this one.** Aim for 140–160 characters, and make it a promise, not a summary. |
| `image` | The 1200×630 social card. Generate it with the script below. Falls back to `/assets/og-default.png`. |
| `image_alt` | Alt text for that card. |
| `subtitle` | Renders under the title; also a good place for the long-tail phrasing. |
| `seo_title` | Replaces the `<title>` tag verbatim (no site-name suffix). Use it when `title · Enzo Barros Bellissimo` would exceed 65 characters; the `<h1>` and social cards keep using `title`. |
| `tags: [a, b]` | Rendered as chips, emitted as `article:tag` + schema `keywords`. |
| `category` | Schema `articleSection`. Defaults to `Essays`. |
| `last_modified_at` | Sets `dateModified`. Add it when you meaningfully revise an old post — freshness is a ranking input. |
| `canonical_url` | Point elsewhere when a piece is cross-posted and the other copy is the original. |
| `noindex: true` | Keep a page out of search results (it stays crawlable and keeps passing links). |

### Social cards

```bash
python3 tools/make-og.py "AI to Find the Right Square" \
    assets/og-ai-to-find-the-right-square.png --eyebrow "Essay"
```

Then set `image: /assets/og-ai-to-find-the-right-square.png` in the post.
Requires `rsvg-convert` (`apt install librsvg2-bin`).

## How the SEO is wired

`{% seo %}` from *jekyll-seo-tag* has been replaced by `_includes/head-seo.html`,
so every signal is explicit and overridable per page. It emits:

- `<title>` and `<meta description>` with per-page fallbacks
- `rel=canonical` on every URL
- `robots` with `max-image-preview:large` (this is what lets Google show the
  card image in results)
- full Open Graph + `summary_large_image` Twitter cards, with real image
  dimensions so nothing re-crops
- `article:published_time` / `modified_time` / `section` / `tag`
- `rel="me"` links to GitHub and LinkedIn
- a reciprocal `hreflang` cluster + `x-default`, and `og:locale` /
  `og:locale:alternate`, driven by `ref`
- one consolidated schema.org `@graph` — `Person` → `WebSite` → `Blog` →
  `BlogPosting` → `WebPage` → `BreadcrumbList`, cross-referenced by `@id` so
  search engines resolve them as one identity instead of six loose nodes

Supporting files:

| File | Purpose |
| --- | --- |
| `robots.txt` | Allows answer engines (GPTBot, ClaudeBot, PerplexityBot…) on purpose, blocks SEO scrapers, points at the sitemap. |
| `sitemap.xml` | Generated by *jekyll-sitemap*, both languages. 404 and the feeds are excluded via `sitemap: false`. |
| `llms.txt` | Machine-readable index for AI answer engines, grouped by language and stating that the two trees are translations of each other. |
| `site.webmanifest` | Icons, theme colours, install metadata. |
| `feed.xml`, `pt/feed.xml` | Full-text Atom, one per language, from `_layouts/feed.xml`. |

### Where the languages live

| File | Purpose |
| --- | --- |
| `_data/i18n.yml` | Every string the chrome renders, plus each language's headline, tagline, description, location and URLs. If a human-readable word appears in a layout, it belongs here. |
| `_includes/i18n.html` | The prelude. Sets `lang`, `t` (the string table), `all_docs` and `lang_posts`. Include it at the top of any layout that renders text — Jekyll renders layouts inside-out, so each one needs its own. |
| `_includes/lang-switch.html` | The PT/EN control, resolved through `ref`. |
| `_layouts/home.html` | The home page for *any* language; `index.html` and `pt/index.html` are front matter only, so they cannot drift. |

*jekyll-feed* was dropped: its per-collection feeds inherit `site.lang`,
`site.description` and the root URL, so the Portuguese feed came out labelled
`xml:lang="en"`, subtitled in English and titled "… | Pt_posts". None of that
is configurable per collection.

**Adding a third language** is a block in `_data/i18n.yml` (including its
`collection:` key), a collection in `_config.yml`, and three front-matter-only
stubs (home, about, feed). No layout changes.

Identity lives in one place — `social_profiles` in `_config.yml` — and feeds the
footer links, the `rel="me"` tags, `llms.txt`, and the schema `sameAs` at once.
Add a profile there and it appears everywhere.

## Preview locally

```bash
gem install jekyll jekyll-sitemap
jekyll serve
```

Verified to build byte-identically on Jekyll 4.4.1 and on the `github-pages`
gem (Jekyll 3.10.0), which is what actually runs in production.

## Validate before pushing

```bash
jekyll build && python3 tools/validate-seo.py
```

851 assertions over the built site: title and description lengths, canonical /
robots / Open Graph / Twitter completeness, JSON-LD parseability and `@id`
integrity, sitemap-versus-canonical agreement, Atom validity, `robots.txt`
directives, manifest icons, `llms.txt`, internal link resolution, 1200x630 card
dimensions, and a guard that no page is ever stamped with the build clock.
Exits non-zero on any failure, so it drops straight into CI.

The i18n layer is checked too, and these are the ones worth understanding:

- `<html lang>`, `og:locale` and every schema `inLanguage` must agree with the
  tree the page was built into — a page in the wrong language demotes the
  whole cluster
- every `hreflang` URL was actually built (never advertise a 404)
- every cluster is **reciprocal**: if A names B, B must name an identical
  cluster, and `x-default` must resolve to the English version
- the two feeds never mix languages, and neither is stamped with the build clock
